# MXVI instructions for AI agents

This document is the compact behavioral contract for AI systems generating
MXVI interfaces, graphics, or implementation code. The goal: anything you
build must look **identical to moisesbaldenegro.com**, in any technology.

## Read first

1. [Visual DNA](/catalog/visual-dna) (`catalog/visual-dna.md`) — the traits
   that make something look MXVI.
2. [Component catalog](/catalog/) (`catalog/`) — every component with its
   exact visual spec and reference markup.
3. The guide for the target platform: `platforms/web/`,
   `platforms/desktop/` or `platforms/mobile/`.

A ready-to-paste prompt is in [Master prompt](/catalog/master-prompt).

## Look (non-negotiable)

- Page background `#070716` (indigo night). Surfaces `#101018`. Never pure
  black or neutral grey backgrounds.
- Text `#ffffff`; secondary text `#b8b8c5`.
- Borders: 1px `rgba(255,255,255,.08)`; strong borders 1px
  `rgba(255,255,255,.15)`.
- Single accent: plum `#B37AC2` (hover `#C396CF`) for active borders, tags,
  links, focus, underlines and markers. Never as a button or block fill.
- **Square corners everywhere** (`border-radius: 0`).
- Typography (Geist family):
  - Geist Pixel (Circle), weight 400, no synthetic bold: h1, h2, navbar
    links, card titles, tags, kicker, search input.
  - Geist Sans: body and UI; h3 at 600–800.
  - Geist Mono: code, `@handles`, small metadata, footer bottom bar.
  - Labels and brand-tile titles: UPPERCASE, `letter-spacing: .08em`.
- Hero atmosphere: radial gradient `#3C1F44` → `#150A18` → `#05050b`, a 1px
  dot grain every 14px at 3 % white, and a glow `rgba(108,56,122,.35)`.
- Spacing unit 14px (`--gap-card`) and its multiples; container
  `min(1500px, 95%)`.
- Shadows: rest `inset 0 1px 0 rgba(255,255,255,.05), 0 18px 40px rgba(0,0,0,.28)`;
  hover `inset 0 1px 0 rgba(255,255,255,.233), 0 25px 60px rgba(0,0,0,.38)`.
- Transitions: `.28s cubic-bezier(.2,.8,.2,1)`; honor reduced motion.

## Implementation

- Web: link `/mxvi/mxvi.css` and use the `.mx-*` classes from the catalog.
  The HTML in the catalog is canonical; framework tabs only adapt syntax.
- Other technologies: reproduce the exact values from the catalog specs and
  [Use in any technology](/catalog/install).
- Prefer an existing catalog component over a new one. Compose bigger pieces
  from atoms and molecules.
- Do not invent tokens. If something is missing, propose a documented
  addition.
- Do not replace real content with decorative placeholders.

## Accessibility

Target WCAG 2.2 AA: semantic HTML, keyboard navigation, visible focus (2px
`#B37AC2` ring, 2px offset), reduced motion, accessible names, non-color
status cues.

## Platforms

Identify the target platform before designing or coding and follow its guide:

- Web (browser sites and web apps): `platforms/web/` or `/llms-web.txt`.
- Desktop (installed Windows, macOS or Linux apps): `platforms/desktop/` or `/llms-desktop.txt`.
- Mobile (installed iOS or Android apps): `platforms/mobile/` or `/llms-mobile.txt`.

The look is the same everywhere; layout, navigation, input, component sizing
and OS conventions follow the platform guide. A website opened on a phone
follows the web guide.

## Output checklist

Before finishing, report:
- target platform (web, desktop or mobile);
- catalog components used;
- tokens used;
- responsive or adaptive behavior for that platform;
- accessibility considerations;
- deviations or proposed additions.

# ADN visual

Estos son los rasgos que hacen que una interfaz se vea MXVI. Si un producto
cumple todos, se ve como [moisesbaldenegro.com](https://moisesbaldenegro.com)
aunque esté hecho en otra tecnología. Si rompe uno, deja de verse MXVI.

## 1. Noche índigo, no negro puro

- Fondo de página `#070716`: casi negro con un tinte índigo.
- Superficies de tarjetas `#101018`, apenas más claras que el fondo.
- Nunca uses `#000000` ni grises neutros para fondos.

## 2. Líneas finas en lugar de cajas pesadas

- Los contenedores se separan con bordes de **1px blanco al 8 %**
  (`rgba(255,255,255,.08)`); los que necesitan más presencia usan **15 %**.
- No hay rellenos de color en las tarjetas ni divisores gruesos.

## 3. Esquinas rectas en todo

- **Radio 0** en tarjetas, botones, campos, tags, imágenes, menús e incluso en
  la barra de desplazamiento. Es la regla más reconocible del sistema.

## 4. Un solo acento: ciruela

- El acento es `#B37AC2` (hover `#C396CF`). Se usa en bordes activos, tags,
  enlaces, el anillo de foco, el subrayado de la navegación y los marcadores.
- El acento ocupa poco espacio: es una señal, no un fondo.
- El azul `#0071e3` existe solo como CTA de las tarjetas promocionales.

## 5. Tres caras de Geist

| Cara | Uso |
|---|---|
| **Geist Pixel (Circle)** | Títulos h1 y h2, enlaces de la navbar, títulos de tarjeta, tags, kicker, búsqueda, etiquetas de columna del footer. Siempre en peso 400, sin negrita sintética. |
| **Geist Sans** | Todo el texto de lectura e interfaz; títulos h3 en 600–800. |
| **Geist Mono** | Código, handles (`@usuario`), metadatos pequeños, barra inferior del footer, ubicación. |

Los títulos de tarjetas y las etiquetas van en **MAYÚSCULAS** con
`letter-spacing: 0.08em`.

## 6. Atmósfera morada en los héroes

- Los bloques principales (hero, header de artículo, perfil, footer, banda de
  logo) llevan un degradado radial que va de `#3C1F44` (ciruela profundo) a
  `#150A18` y `#05050b`.
- Encima, un **grano de puntos** de 1px cada 14px al 3 % de blanco.
- Un **resplandor** radial `rgba(108,56,122,.35)` flota en una esquina.

## 7. Bento de marcas

- El hero es una cuadrícula Bento de 12 columnas con filas de 95px y
  separación de 14px.
- Cada tarjeta de marca tiene el color de su tecnología, un título pequeño en
  mayúsculas arriba a la izquierda y el **logo gigante, rotado y recortado**
  saliendo por la esquina inferior derecha.

## 8. Profundidad sutil

- Tarjetas en reposo: sombra suave con un brillo interior de 1px arriba
  (`inset 0 1px 0 rgba(255,255,255,.05)`).
- Al pasar el mouse: borde de acento o más fuerte, sombra mayor y, en
  tarjetas grandes, elevación de 2–4px.
- El glow morado aparece solo en acciones principales (hover del botón de
  acento) y en el foco de la búsqueda.

## 9. Un ritmo: múltiplos de 14

- La unidad base es **14px**. Separaciones y paddings son múltiplos: 3.5, 7,
  10.5, 14, 21, 28, 35, 42, 56, 70px.
- El contenido vive en un contenedor de `min(1500px, 95%)` centrado.

## 10. Movimiento con una sola curva

- Todas las transiciones duran **0.28s** con `cubic-bezier(.2,.8,.2,1)`.
- Los movimientos son cortos: subrayados que crecen, flechas que se desplazan
  2px, tarjetas que suben 4px.
- Con "reducir movimiento" todo se vuelve instantáneo.

## Señales de que algo NO es MXVI

- Esquinas redondeadas.
- Botones rellenos de morado o degradados en botones.
- Fondos negro puro o grises neutros.
- Títulos en una fuente que no sea Geist Pixel.
- Bordes grises opacos en lugar de blanco translúcido.
- Varias fuentes de acento compitiendo (cian, verde, rosa) fuera de las
  tarjetas de marca.
- Sombras de colores en reposo.

# Web

Guía de MXVI para productos que corren en un navegador: sitios de marca,
landing pages, documentación y aplicaciones web. Una aplicación web abierta en
un teléfono también sigue esta guía, usando su layout compacto.

## Tipos de producto web

| Tipo | Prioridad | Expresión MXVI |
|---|---|---|
| Sitio de marca / landing | Historia y conversión | Espaciosa, editorial, composición Bento |
| Documentación | Encontrar y entender | Estructurada, legible, técnica |
| Aplicación web | Completar tareas | Funcional, densidad equilibrada |
| Dashboard | Monitorear y decidir | Densidad equilibrada o compacta, datos primero |

## Páginas de esta guía

1. [Layout y responsive](/platforms/web/layout)
2. [Navegación](/platforms/web/navigation)
3. [Componentes en web](/platforms/web/components)
4. [Interacción y accesibilidad](/platforms/web/interaction)
5. [Checklist de revisión](/platforms/web/checklist)

## Contrato para agentes (web)

Este bloque es suficiente para trabajos pequeños. Para trabajos grandes, lee la
guía completa o `/llms-web.txt`.

**Look (idéntico a moisesbaldenegro.com)**

- Fondo `#070716`, superficie `#101018`; bordes 1px blanco al 8 % y al 15 %.
- Texto `#ffffff`, secundario `#b8b8c5`.
- Acento único ciruela `#B37AC2` (hover `#C396CF`); nunca como relleno.
- **Esquinas rectas en todo** (radio 0).
- Geist Pixel para títulos, navegación, títulos de tarjeta y tags; Geist Sans
  para texto e interfaz; Geist Mono para código y metadatos.
- Atmósfera de héroes: degradado `#3C1F44` → `#150A18` → `#05050b` con grano
  de puntos y glow `rgba(108,56,122,.35)`.
- Espaciado en múltiplos de `14px`.
- Transición única `.28s cubic-bezier(.2,.8,.2,1)`.
- Detalle completo: [ADN visual](/catalog/visual-dna) y
  [Catálogo](/catalog/).

**Reglas web**

1. Usa `mxvi.css` y los componentes `.mx-*` del [catálogo](/catalog/); los
   valores salen de los [tokens](/implementation/css-tokens).
2. Diseña mobile-first con los cortes del sitio: 600, 768, 900, 970 y
   1200px ([layout](/platforms/web/layout)).
3. HTML semántico: `<a>` para navegar, `<button>` para acciones, encabezados en
   orden y landmarks (`header`, `nav`, `main`, `footer`).
4. Todo funciona con teclado y tiene foco visible (`:focus-visible`).
5. El hover es una mejora; nada depende solo de hover.
6. Objetivos táctiles de al menos `44 × 44 px` en layouts compactos.
7. Respeta `prefers-reduced-motion`.
8. El estado navegable (páginas, filtros, pestañas relevantes) vive en la URL.
9. Objetivo: WCAG 2.2 AA.
10. Reporta tokens usados, comportamiento responsive, accesibilidad y
    desviaciones.

## Qué no hacer

- Forzar un layout de marketing en una aplicación funcional.
- Usar todos los acentos con la misma intensidad.
- Reconstruir el logo con una fuente: usa el [SVG oficial](/brand/logo).
- Poner texto largo en Geist Mono o Geist Pixel.
- Redondear esquinas.
- Ocultar contenido esencial detrás de hover o de animaciones.

# Web: layout y responsive

## Contenedor y cortes

Todo el contenido vive en un contenedor de `min(1500px, 95%)` centrado: el
margen lateral es el 2.5 % del ancho de la ventana. Los cortes son los de
[Spacing & layout](/foundations/spacing-layout):

| Ancho | Qué cambia |
|---|---|
| ≤ 599px | Footer en 1 columna |
| ≤ 768px | Bento en 1 columna, header de artículo apilado, promos en 1 columna, paddings de página 32px / 48px |
| ≥ 769px | Línea de tiempo con línea vertical |
| ≥ 900px | Cuadrículas de tarjetas a 3 columnas, cifras a 4, footer completo, perfil en 2 columnas |
| ≤ 969px | Navbar con menú ☰ |
| ≤ 1200px | Bento a 6 columnas |

## Mobile-first

1. Diseña primero el layout de una sola columna.
2. Agrega columnas en los cortes de arriba.
3. Mantén el mismo orden de lectura en todos los tamaños; el orden visual no
   debe contradecir el orden del HTML.
4. Nunca debe aparecer scroll horizontal en la página. Las tablas anchas hacen
   scroll dentro de su propio contenedor.

## Ritmo vertical

| Bloque | Espaciado |
|---|---|
| Página de listado (`.mx-page`) | 48px arriba, 64px abajo (32px / 48px en ≤ 768px) |
| Entre secciones (`.mx-stack`) | 28px |
| Título de sección → contenido (`.mx-section`) | 21px |
| Entre tarjetas | 14px |
| Contenido → footer | 70px |

## Composición Bento

El [hero Bento](/catalog/organisms/hero-bento) es la firma de la portada:

- 12 columnas, filas de 95px, separación 14px.
- La tarjeta de perfil va primero (5 × 6); el resto mezcla tarjetas anchas
  y cuadradas.
- 6 columnas en ≤ 1200px y 1 en ≤ 768px, mostrando solo las tarjetas
  marcadas para móvil.

## Tipografía en web

- Carga `mxvi.css` (incluye Geist, Geist Mono y Geist Pixel autoalojadas, con
  `font-display: swap`).
- Texto de interfaz a 1rem; cuerpo de artículo de 17 a 19px con interlineado
  1.7.
- Títulos en Geist Pixel; ver la escala completa en
  [Typography](/foundations/typography).

## Imágenes y media

- Usa `width` y `height` (o `aspect-ratio`) para evitar saltos de layout.
- Sirve tamaños adecuados con `srcset`/`sizes`.
- Carga diferida (`loading="lazy"`) para imágenes fuera de la primera pantalla.
- El logo siempre es el [SVG oficial](/brand/logo).

# Web: navegación

Aplica los patrones de [Navigation](/components/navigation) con las
convenciones del navegador.

## Estructura

| Patrón | Uso en web |
|---|---|
| Barra superior | Destinos principales del sitio o aplicación, logo y acciones globales (búsqueda, cuenta). |
| Sidebar | Secciones dentro de documentación o aplicaciones con muchas áreas. En Compact se convierte en un panel desplegable. |
| Pestañas | Vistas hermanas dentro de un mismo contexto. |
| Breadcrumbs | Ubicación dentro de jerarquías profundas (documentación, catálogos). |
| Paginación | Listas largas cuando el usuario necesita volver a un punto concreto. |

## Reglas

1. **La URL es parte de la navegación.** Cada página y cada estado que el usuario
   querría compartir o recargar (filtros, pestañas, búsqueda) tiene su propia URL.
2. Los botones "atrás" y "adelante" del navegador deben funcionar.
3. Usa `<a href>` para ir a otro lugar y `<button>` para ejecutar acciones.
4. Marca la ubicación actual visualmente y con `aria-current="page"`.
5. Agrupa la navegación principal en un `<nav>` con nombre accesible.
6. Agrega un enlace "Saltar al contenido" al inicio de la página.
7. Los menús no se abren solo con hover; deben abrirse con clic y teclado.

## Navegación en Compact

- Muestra el logo y un botón de menú con nombre accesible ("Menú") y
  `aria-expanded`.
- El menú abierto atrapa el foco mientras está abierto, se cierra con `Escape`
  y devuelve el foco al botón.
- Mantén visibles las acciones críticas (por ejemplo búsqueda) si caben.

## Logo

- El logo en la barra superior enlaza al inicio.
- Usa el SVG oficial con sus colores originales; respeta la zona libre de
  [Logo](/brand/logo).

# Web: componentes

Los contratos de [Components](/components/overview) aplican igual. Esta página
explica cómo implementarlos en web.

## Botones

- Alturas: `32` (pequeño), `40` (mediano) y `48 px` (grande).
- En Compact, los botones principales usan al menos `44 px` de alto o un área
  táctil equivalente.
- Usa `<button type="button">` o `type="submit"` dentro de formularios.
- Estado de carga: deshabilita el envío duplicado y anuncia el progreso
  (`aria-busy` o texto).
- Radio 0 (esquinas rectas). Variantes y specs en [Botones](/catalog/atoms/buttons).

## Campos

- Usa controles nativos (`<input>`, `<select>`, `<textarea>`) siempre que sea
  posible.
- Cada campo tiene `<label>` visible; el placeholder nunca lo sustituye.
- Usa el `type` y el `autocomplete` correctos (`email`, `tel`,
  `current-password`, etc.); en teléfonos esto abre el teclado adecuado.
- Los errores se asocian al campo con `aria-describedby` y no dependen solo del
  borde rojo.
- En Compact, el texto de los campos debe ser de al menos `16 px`.

## Tarjetas y paneles

- Superficie `--color-surface`, borde `--color-border`; ver [Tarjetas](/catalog/molecules/cards).
- Una tarjeta clicable entera usa un enlace con nombre accesible; si tiene
  varias acciones, no hagas clicable toda la tarjeta.
- En Compact, las tarjetas ocupan todo el ancho disponible.

## Feedback

- **Toasts:** en una región `aria-live`; nunca con información esencial.
- **Alertas:** en línea, con título o etiqueta de estado y `role="alert"` solo
  si requieren atención inmediata.
- **Diálogos:** usa `<dialog>` o un patrón equivalente con foco atrapado,
  `Escape` para cerrar y devolución del foco al disparador.
- **Progreso:** `<progress>` o `role="progressbar"` con valor si se conoce.

## Tablas y datos

- Usa `<table>` con encabezados `<th scope>` para datos tabulares.
- En Compact, la tabla hace scroll horizontal dentro de su contenedor o se
  transforma en una lista de tarjetas.
- Números en `font-variant-numeric: tabular-nums`; identificadores y versiones
  en Geist Mono.

## Íconos

- Íconos decorativos con `aria-hidden="true"`.
- Botones solo con ícono necesitan `aria-label`.

# Web: interacción y accesibilidad

El objetivo para todo producto web es **WCAG 2.2 AA**. Esta página complementa
[Accessibility](/foundations/accessibility).

## Métodos de entrada

En web no sabes con qué interactúa el usuario: puede ser mouse, teclado,
táctil, lector de pantalla o una combinación. Diseña para todos.

| Entrada | Reglas |
|---|---|
| Teclado | Todo es alcanzable con `Tab`, en orden lógico. Foco visible con `:focus-visible`. Sin trampas de foco fuera de diálogos. |
| Mouse | El hover agrega información o feedback, pero nunca es la única forma de acceder a algo. |
| Táctil | Objetivos de al menos `44 × 44 px`, separación suficiente entre ellos y sin gestos obligatorios sin alternativa. |
| Lector de pantalla | HTML semántico, nombres accesibles, regiones `aria-live` para cambios dinámicos. |

## Foco

- Anillo de foco: 2px `#B37AC2` con 2px de separación (global en `base.css`).
- No uses el glow como único indicador de foco.
- Al abrir un diálogo, el foco entra en él; al cerrarlo, regresa al disparador.

## Movimiento

- Transición única `.28s cubic-bezier(.2,.8,.2,1)` de [Motion](/foundations/motion).
- Con `prefers-reduced-motion: reduce`, elimina o reduce animaciones no
  esenciales.
- Sin parallax que estorbe la lectura y sin destellos.

## Preferencias del usuario

- MXVI es oscuro por defecto. Si el producto ofrece tema claro, guarda la
  elección del usuario y respeta `prefers-color-scheme` como valor inicial.
- Respeta el zoom del navegador hasta 200 % sin perder contenido.
- Soporta `forced-colors` (modo de alto contraste de Windows): los bordes y el
  foco deben seguir visibles.

## Rendimiento

El rendimiento también es experiencia:

- Evita saltos de layout reservando espacio para imágenes y fuentes.
- No bloquees la primera pantalla con animaciones o scripts grandes.
- Muestra estados de carga en operaciones de más de un segundo.

## Validación

- Pruebas automáticas (por ejemplo axe) en cada cambio de UI.
- Recorrido manual con teclado.
- Prueba con un lector de pantalla (NVDA, VoiceOver o TalkBack según el
  público).

# Web: checklist de revisión

Usa esta lista antes de dar por terminada una interfaz web. Los agentes de IA
deben reportar cada punto.

## Marca y tokens

- [ ] Colores, tipografía, espaciado y radios salen de los tokens de `mxvi/tokens.css`.
- [ ] Todas las esquinas son rectas y los títulos usan Geist Pixel.
- [ ] Se usaron componentes del catálogo en lugar de crear nuevos.
- [ ] Los acentos se usan con moderación (5–10 % de la composición).
- [ ] El logo es el SVG oficial con sus colores originales.
- [ ] No hay valores sueltos sin justificar.

## Layout

- [ ] Funciona en 390, 768, 1200 y 1440 px de ancho.
- [ ] No hay scroll horizontal en la página.
- [ ] El orden de lectura es el mismo en todos los tamaños.
- [ ] La densidad corresponde al tipo de producto.

## Navegación

- [ ] Cada página o estado compartible tiene URL.
- [ ] "Atrás" y "adelante" del navegador funcionan.
- [ ] La ubicación actual está marcada (`aria-current`).
- [ ] El menú compacto se abre y cierra con teclado y con `Escape`.

## Accesibilidad

- [ ] Todo es operable con teclado y el foco es visible.
- [ ] Encabezados en orden y landmarks presentes.
- [ ] Campos con etiqueta visible y errores asociados.
- [ ] El color nunca es la única señal de estado.
- [ ] Contraste AA verificado en las combinaciones reales.
- [ ] `prefers-reduced-motion` respetado.
- [ ] Objetivos táctiles de `44 × 44 px` en Compact.

## Reporte del agente

- Plataforma: **web**.
- Tokens usados.
- Componentes y patrones reutilizados.
- Comportamiento responsive.
- Consideraciones de accesibilidad.
- Desviaciones o adiciones propuestas.

# Usar en cualquier tecnología

MXVI es un **lenguaje visual**. En web se implementa con una hoja de estilos
sin dependencias; en cualquier otra tecnología se reproduce con los mismos
valores. No requiere ningún framework.

## Web: una sola hoja de estilos

```html
<link rel="stylesheet" href="https://moibaldenegro.github.io/mxvi-design-system/mxvi/mxvi.css">
<!-- Opcional: menú móvil, limpiar búsqueda y copiar código -->
<script src="https://moibaldenegro.github.io/mxvi-design-system/mxvi/mxvi.js" defer></script>
```

Puedes importar solo lo que uses, por ejemplo
`@import './mxvi/components/atoms/buttons.css';` después de `tokens.css`.

Para producción, descarga el paquete de la plataforma (incluye la carpeta
`mxvi/` con CSS, JS, fuentes y assets) y sírvelo desde tu propio dominio:

```text
mxvi/
├── mxvi.css          ← fuentes + tokens + base + componentes
├── tokens.css        ← solo variables
├── base.css          ← reset y estilos globales
├── components.css    ← índice de componentes (@import)
├── components/       ← un archivo por componente (≤ 100 líneas):
│   ├── atoms/        ← buttons, typography, tags, inputs, media
│   ├── molecules/    ← cards, search, navigation, brand-tile...
│   └── organisms/    ← navbar, footer, hero, post, prose, promo...
├── fonts.css         ← @font-face de Geist
├── mxvi.js           ← comportamientos opcionales
├── fonts/            ← Geist, Geist Mono, Geist Pixel (OFL 1.1)
└── assets/           ← logo.svg, sprite.svg
```

### Por framework

Las clases son CSS puro, así que funcionan igual en cualquier framework. Solo
cambia cómo se importa la hoja:

::: code-group

```html [HTML]
<link rel="stylesheet" href="/mxvi/mxvi.css">
<script src="/mxvi/mxvi.js" defer></script>
```

```tsx [React / Next.js]
// app/layout.tsx o main.tsx
import './mxvi/mxvi.css'

// En JSX usa className en lugar de class:
<a className="mx-button mx-button--accent" href="/cv.pdf">Descargar CV</a>
```

```ts [Vue / Nuxt]
// main.ts (Vue) o nuxt.config.ts → css: ['~/mxvi/mxvi.css']
import './mxvi/mxvi.css'
```

```svelte [Svelte / SvelteKit]
<!-- src/routes/+layout.svelte -->
<script>
  import '../mxvi/mxvi.css'
</script>
<slot />
```

```json [Angular]
// angular.json → projects.<app>.architect.build.options
"styles": ["src/mxvi/mxvi.css"]
```

```astro [Astro]
---
// src/layouts/Layout.astro
import '../mxvi/mxvi.css'
---
```

:::

### Comportamientos (JS)

`mxvi.js` es opcional y solo lee atributos `data-*`. Si tu framework maneja el
estado, reimplementa el mismo contrato:

| Componente | Contrato |
|---|---|
| Menú móvil de la navbar | Botón `[data-mx-menu-toggle]` dentro de `.mx-navbar`. Al abrir: `data-menu="open"` en la navbar y `aria-expanded="true"` en el botón. `Escape` cierra y devuelve el foco al botón. |
| Búsqueda | Clase `is-filled` en `.mx-search` cuando el input tiene texto; el botón `[data-mx-clear]` vacía el input y le da foco. |
| Copiar código | Botón `[data-mx-copy]` dentro de `.mx-code`: copia el `<pre>`, añade `is-copied` y muestra "Copiado" durante 2 s. |

Si renderizas contenido después de la carga (SPA), llama a
`window.MXVI.init(contenedor)`.

# Botones

**Nivel:** átomo · **Clase base:** `.mx-button`

Botones y enlaces con forma de botón. Todos tienen **esquinas rectas**, texto
Geist Sans en peso 600 y bordes finos; ninguno tiene relleno de color salvo el

| Variante | Clase | Cuándo usarla |
|---|---|---|
| Contorno | `.mx-button` | Acciones secundarias y enlaces con ícono (redes sociales). |

  padding vertical si hace falta).

| Verificado `.mx-verified` | Dentro del handle | 0.6rem | `#ffffff` | — | `#0a6f9e` | cuadro de 16×16px |

</div>

## Reglas

- Los tags pueden ser enlaces (`<a class="mx-tag">`); al pasar el mouse el
  borde cambia a `#B37AC2`.
- Agrupa varios con [`.mx-tag-list` o `.mx-chip-list`](/catalog/molecules/navigation#lista-de-tags).
- El check del handle lleva un texto oculto ("Verificado") para lectores de
  pantalla.
- El cian del handle es exclusivo de la identidad del usuario: no lo uses en
  otros elementos.

# Barra de búsqueda

**Nivel:** molécula · **Clase:** `.mx-search` · **Compuesta por:** campo,
ícono de lupa y botón de limpiar

Escribe en el campo para ver el botón ×; con el foco y texto, la lupa
"escanea" en bucle.

```html preview
<search class="mx-search">
  <form class="mx-search__form" action="/search" method="get">
    <svg class="mx-search__icon" aria-hidden="true" focusable="false" width="16" height="16" viewBox="0 0 20 20" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round">
      <circle cx="8.5" cy="8.5" r="7" />
      <path d="M13.5 13.5 19 19" />
    </svg>
    <input class="mx-search__input" type="search" name="q" enterkeyhint="search" placeholder="Buscar artículos…" aria-label="Buscar artículos">
    <button class="mx-search__clear" type="button" data-mx-clear aria-label="Limpiar búsqueda">×</button>
  </form>
</search>
```

Ancho completo (`.mx-search--block`), por ejemplo dentro del menú móvil:

```html preview
<search class="mx-search mx-search--block">
  <form class="mx-search__form" action="/search" method="get">
    <svg class="mx-search__icon" aria-hidden="true" focusable="false" width="16" height="16" viewBox="0 0 20 20" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round">
      <circle cx="8.5" cy="8.5" r="7" />
      <path d="M13.5 13.5 19 19" />
    </svg>
    <input class="mx-search__input" type="search" name="q" placeholder="Buscar artículos…" aria-label="Buscar artículos">
    <button class="mx-search__clear" type="button" data-mx-clear aria-label="Limpiar búsqueda">×</button>
  </form>
</search>
```

## Especificación visual

<div class="mx-spec">

| Parte | Valor |
|---|---|
| Campo | 240px de ancho (100 % en `--block` y en móvil), padding 10px 42px |
| Fondo y borde | `#101018`, 1px blanco 8 %, radio 0 |
| Texto | **Geist Pixel** .95rem `#ffffff`; placeholder `#b8b8c5` |
| Lupa | 16 × 16px a 16px del borde izquierdo, trazo 2px, `#b8b8c5` |
| Foco | borde `#B37AC2` + halo `0 0 0 4px rgba(108,56,122,.35)`; lupa `#B37AC2` y escala 1.12 |
| Con texto y foco | la lupa se mueve en bucle (1.6s): desplazamiento de 3px y rotación de ±10° |
| Con texto sin foco | lupa `#B37AC2` quieta |
| Botón × | 32 × 32px a 6px del borde derecho, `#b8b8c5`; hover `#B37AC2`; oculto sin texto |

</div>

## Comportamiento

- Es un formulario `GET` a `/search?q=`: funciona sin JavaScript.
- Con [`mxvi.js`](/catalog/install#comportamientos-js), la clase `is-filled`
  muestra el botón × y este vacía el campo.
- El landmark `<search>` y el `aria-label` del campo le dan nombre accesible;
  la lupa es decorativa.
- Con "reducir movimiento" la lupa no se anima.

# Bloques de contenido

**Nivel:** molécula · **Clases:** `.mx-callout`, `.mx-quote`, `.mx-notice`,
`.mx-code`, `.mx-timeline-item`

## Callout

Nota destacada dentro de una tarjeta, con una barra de acento a la izquierda.

```html preview
<p class="mx-callout"><strong>Resultado:</strong> Sistema en producción en septiembre de 2025: optimizó procesos administrativos y aumentó márgenes.</p>
```

- Fondo `#070716` (más oscuro que la tarjeta), barra izquierda de 3px
  `#B37AC2`, padding 10.5px 14px, interlineado 1.6.
- El texto en `<strong>` va en `#C396CF`.

## Cita

Frase destacada (filosofía, testimonio).

```html preview
<blockquote class="mx-quote">
  <p class="mx-quote__text" lang="en">Deterministic Engineering in an Agentic World</p>
  <p class="mx-quote__caption">Uso la IA para construir software, pero con procesos verificables: specs primero, tests antes que el código y una feature a la vez.</p>
</blockquote>
```

<div class="mx-spec">

| Parte | Valor |
|---|---|
| Contenedor | `#101018`, borde 1px blanco 8 % con barra izquierda de **4px** `#B37AC2`, padding 28px 35px (21px en ≤ 768px) |
| Frase | Geist Sans 800 `clamp(1.5rem, 1.1rem + 1.8vw, 2.5rem)`, `letter-spacing: -.02em`; comillas “ ” en `#C396CF` |
| Texto | 1.1rem `#b8b8c5`, máximo 70 caracteres por línea |

</div>

Estado vacío, guía o página de error.


```html preview
<section class="mx-notice">
```

## Especificación visual

<div class="mx-spec">

| Parte | Valor |
|---|---|

## Comportamiento y accesibilidad

- "Saltar al contenido" es el primer elemento: invisible hasta recibir foco,
  aparece arriba a la izquierda con fondo `#B37AC2`.
- El enlace de la página actual lleva `aria-current="page"`.
- Botón ☰/✕ con `aria-expanded` y `aria-controls`; `Escape` cierra el panel y
  devuelve el foco ([contrato de `mxvi.js`](/catalog/install#comportamientos-js)).
- Sin JavaScript, en móvil los enlaces se acomodan en varias líneas y la
  búsqueda ocupa todo el ancho.
- Los enlaces externos llevan "(sitio externo)" oculto.

## Composición

- La tarjeta de perfil va primero y es la más grande (5 × 6 en escritorio).
- Mezcla tamaños: una o dos tarjetas anchas por fila y el resto cuadradas.
- Las tarjetas de marca con enlace llevan la flecha ↗ y abren en otra pestaña.
- En móvil muestra solo las tarjetas más importantes.

# Plataformas

MXVI es un solo sistema de diseño: los mismos fundamentos, tokens, componentes y
reglas de marca aplican en todas partes. Lo que cambia entre plataformas es
**cómo** se aplican: el espacio disponible, la forma de interactuar, los patrones
de navegación que el usuario espera y las convenciones del sistema operativo.

Cada plataforma tiene una guía completa y autocontenida. Algunas reglas se
repiten a propósito: así una persona o un agente de IA puede trabajar con una
sola guía sin tener que reconstruir el contexto desde otras páginas.

## Elige la plataforma

| Plataforma | Cuándo aplica | Guía | Para un LLM (fetch) | Para un proyecto local |
|---|---|---|---|---|
| **Web** | Sitios, landing pages, documentación y aplicaciones que corren en un navegador. | [Web](/platforms/web/) | [`/llms-web.txt`](/llms-web.txt) | [Descargar Markdown (.zip)](/downloads/mxvi-web-markdown.zip) |
| **Escritorio** | Aplicaciones instaladas en Windows, macOS o Linux (nativas, Electron, Tauri u otras). | [Escritorio](/platforms/desktop/) | [`/llms-desktop.txt`](/llms-desktop.txt) | [Descargar Markdown (.zip)](/downloads/mxvi-desktop-markdown.zip) |
| **Móvil** | Aplicaciones para teléfonos y tabletas iOS o Android (nativas o multiplataforma). | [Móvil](/platforms/mobile/) | [`/llms-mobile.txt`](/llms-mobile.txt) | [Descargar Markdown (.zip)](/downloads/mxvi-mobile-markdown.zip) |

Si un producto existe en varias plataformas, aplica la guía de cada una a su
versión correspondiente. Una aplicación web abierta en el navegador de un
teléfono sigue la guía **Web** (con su layout compacto); la guía **Móvil** es
para aplicaciones instaladas.

## Qué se comparte siempre

- Paleta de marca, colores semánticos y proporciones de uso ([Color](/foundations/colors)).
- Tipografías Geist Sans, Geist Mono y Geist Pixel, y la escala tipográfica ([Typography](/foundations/typography)).
- El [catálogo de componentes](/catalog/) y su [ADN visual](/catalog/visual-dna).
- Escala de espaciado `4–64 px` ([Spacing & layout](/foundations/spacing-layout)).
- Radios, bordes, sombras y glow ([Geometry & effects](/foundations/geometry-effects)).
- Duraciones y principios de movimiento ([Motion](/foundations/motion)).
- Requisitos de accesibilidad ([Accessibility](/foundations/accessibility)).
- Contratos y estados de los componentes ([Components](/components/overview)).
- Logo y firma de marca ([Logo](/brand/logo)).

## Qué cambia por plataforma

| Aspecto | Web | Escritorio | Móvil |
|---|---|---|---|
| Entrada principal | Puntero, teclado y táctil | Puntero preciso y teclado | Táctil y gestos |
| Unidad de diseño | CSS px | px del sistema (escalados por el SO) | pt (iOS) / dp (Android) |
| Layout | Responsivo por breakpoints | Ventanas redimensionables | Pantalla completa, orientación y áreas seguras |
| Navegación | URL, barra superior, sidebar, breadcrumbs | Sidebar, pestañas, menús, paleta de comandos | Barra inferior, pilas de navegación, gesto o botón "atrás" |
| Densidad típica | Espaciosa (marketing) o equilibrada (apps) | Equilibrada o compacta | Equilibrada, con objetivos táctiles grandes |
| Tamaño mínimo de control | 44 × 44 px en táctil | 32 px de alto con puntero | 44 pt (iOS) / 48 dp (Android) |
| Hover | Mejora opcional, nunca requisito | Disponible, nunca única vía | No existe |
| Convenciones a respetar | Navegador y estándares web | Sistema operativo (ventanas, menús, atajos) | Guías de iOS y Android |

## Cómo se usa con agentes de IA

Toda la documentación se puede leer aquí y consumir de dos formas.

### 1. En línea: el agente lee la documentación por fetch

1. Identifica la plataforma del trabajo (web, escritorio o móvil).
2. Pide al agente que lea el contexto de esa plataforma:
   `/llms-web.txt`, `/llms-desktop.txt` o `/llms-mobile.txt`. Cada archivo
   incluye las instrucciones para agentes, los fundamentos, los componentes y
   la guía completa de la plataforma en un solo documento.
3. Para trabajos pequeños, basta con el Markdown de la página **Resumen** de la
   plataforma (por ejemplo `/markdown/platforms/web/index.md`), que contiene un
   contrato compacto con los tokens y reglas clave.
4. Cada página de este sitio tiene su Markdown crudo en
   `/markdown/<ruta>.md`; el enlace está al inicio de la página.

Ejemplo de instrucción para el agente:

```text
Antes de escribir UI, lee https://moibaldenegro.github.io/mxvi-design-system/llms-web.txt
y sigue el design system MXVI. Reporta los tokens usados y cualquier desviación.
```

### 2. Local: la documentación vive dentro del proyecto

1. Descarga el `.zip` de la plataforma (tabla de arriba) y descomprímelo en el
   repositorio, por ejemplo en `docs/mxvi/`.
2. El paquete incluye un `AGENTS.md` que indica qué leer primero, los Markdown
   del núcleo común y los de la plataforma, y su `llms-<plataforma>.txt`.
3. Referencia la carpeta desde las instrucciones de tu agente (por ejemplo en
   el `AGENTS.md` o `CLAUDE.md` del proyecto):

```text
Para cualquier interfaz, sigue el design system MXVI en docs/mxvi/.
Empieza por docs/mxvi/AGENTS.md.
```

Los enlaces que empiezan con `/` dentro de los Markdown apuntan a archivos del
paquete: `/foundations/colors` corresponde a `foundations/colors.md`.

Pide siempre al agente que reporte la plataforma usada y cualquier desviación.

## Estado

Las guías de plataforma son una **propuesta v1.0**. Las decisiones marcadas
como **Propuesta** no existían en los fundamentos y deben validarse en
productos reales antes de considerarse estables.

| `#6C387A` / `#090912` | `--color-scrollbar-*` | La barra de desplazamiento |

## Colores semánticos

El sitio todavía no usa estados de éxito, advertencia o error. **Propuesta**
para cuando un producto los necesite (con contraste AA sobre `#101018`):

| Estado | Valor |
|---|---|
| Éxito | `#39C98A` |
| Advertencia | `#F3B64B` |
| Error | `#F05B72` |
| Información | `#5fd6ff` |

Acompáñalos siempre con texto o ícono; el color nunca es la única señal.

## Proporciones

- 85–90 % fondo y superficies oscuras.
- 8–12 % texto y líneas.
- 2–5 % acento.
- Las tarjetas de marca y las promocionales son la única excepción con
  bloques de color sólido.

## Contraste

| Combinación | Contraste |
|---|---|
| `#ffffff` sobre `#070716` | 19.98 : 1 |
| `#b8b8c5` sobre `#101018` | 9.65 : 1 |
| `#B37AC2` sobre `#070716` | 6.17 : 1 |
| `#B37AC2` sobre `#101018` | 5.84 : 1 |
| `#C396CF` sobre `#101018` | 7.74 : 1 |
| `#ffffff` sobre `#0071e3` (CTA) | 4.70 : 1 |

Verifica cualquier combinación nueva contra WCAG 2.2 AA (4.5 : 1 en texto
normal, 3 : 1 en texto grande y gráficos).

## Reglas

- Nunca uses negro puro ni grises neutros como fondo.
- El acento no se usa como fondo de botones ni de bloques grandes.
- Los bordes son siempre blancos translúcidos, nunca grises opacos.
- No agregues acentos nuevos (cian, verde, rosa) fuera de sus usos únicos.

# Tipografía

MXVI usa la familia **Geist** en tres caras, autoalojadas en `mxvi/fonts/`
(licencia SIL Open Font License 1.1).

## Familias

| Token | Cara | Uso |
|---|---|---|
| `--font-display` | **Geist Pixel (Circle)** | h1 y h2, enlaces de la navbar, títulos de tarjeta, tags, kicker, input de búsqueda, etiquetas de columna del footer |
| `--font-sans` | **Geist Sans** (variable 100–900) | Texto de lectura e interfaz, títulos h3, botones |
| `--font-mono` | **Geist Mono** (variable 100–900) | Código, handles (`@usuario`), fechas y metadatos pequeños, barra inferior del footer, ubicación |

Geist Pixel tiene **una sola cara (400)**. Nunca la pongas en negrita ni
cursiva: usa `font-weight: 400` y `font-synthesis: none`.

## Escala

| Rol | Cara | Tamaño | Peso | Interlineado |
|---|---|---|---|---|
| Display (título de artículo) | Pixel | `clamp(2.2rem, 4.5vw, 3.6rem)` | 400 | 1.15 |
| Nombre de perfil | Pixel | `clamp(2rem, 1.4rem + 2.4vw, 3.25rem)` | 400 | 1.1 |
| h1 de página | Pixel | 1.75rem | 400 | 1.2 |
| h2 de sección | Pixel | 1.75rem o `clamp(1.5rem, 1.2rem + 1vw, 2rem)` | 400 | 1.2 |
| Título de tarjeta de artículo | Pixel | 1.35rem | 400 | 1.3 |
| h3 de tarjeta | Sans | 1.05–1.15rem | 700 | 1.35 |
| Cifra destacada | Sans | `clamp(1.75rem, 1.2rem + 1.6vw, 2.5rem)` | 800 | 1.1 |
| Cita | Sans | `clamp(1.5rem, 1.1rem + 1.8vw, 2.5rem)` | 800 | 1.2 |
| Cuerpo de artículo | Sans | `clamp(1.0625rem, 1rem + .3vw, 1.1875rem)` (17→19px) | 400 | 1.7 |
| Texto de interfaz | Sans | 1rem | 400 | 1.55 |
| Navegación | Pixel | .95rem (.85rem en ≤ 969px) | 400 | normal |
| Metadatos | Sans | .85–.9rem | 400 | normal |
| Etiqueta / título de tarjeta de marca | Pixel | .85–.95rem, MAYÚSCULAS, `letter-spacing: .08em` | 400 | normal |
| Tag | Pixel | .78–.85rem | 400 | normal |
| Mono pequeño | Mono | .75–.8rem | 400–600 | normal |

## Reglas

- Títulos de sección en Geist Pixel; nunca en Sans ni Mono.
- Etiquetas y títulos de tarjetas de marca en MAYÚSCULAS con
  `letter-spacing: .08em`.
- Texto largo en Geist Sans, con interlineado de 1.55 a 1.7.
- Usa `text-wrap: balance` en títulos grandes y `pretty` en párrafos.
- Un solo `h1` por página.
- No uses Geist Mono para párrafos ni Geist Pixel para texto largo.

## Carga

```css
@import url('/mxvi/fonts.css');  /* o mxvi.css, que ya la incluye */
```

En otras plataformas registra los archivos de `mxvi/fonts/`:
`Geist-Variable.woff2`, `Geist-Italic-Variable.woff2`,
`GeistMono-Variable.woff2` y `GeistPixel-Circle.woff2`.

# Espaciado y layout

## Unidad base: 14px

Todo el espaciado sale de un token: `--gap-card: 14px`. Separaciones y
paddings son múltiplos de él.

| Múltiplo | Valor | Uso típico |
|---|---:|---|
| × 0.25 | 3.5px | Padding vertical de chips y badges |
| × 0.33 | 4.7px | Separación cifra–etiqueta |
| × 0.5 | 7px | Separación ícono–texto, entre chips |
| × 0.75 | 10.5px | Entre elementos de una lista, padding de chips |
| × 1 | 14px | Separación de tarjetas en cuadrículas, márgenes de títulos |
| × 1.5 | 21px | Padding de tarjetas, separación entre título y contenido de sección |
| × 2 | 28px | Separación entre secciones |
| × 2.5 | 35px | Padding de citas, separación de filas del footer |
| × 3 | 42px | Padding vertical de página (arriba) |
| × 4 | 56px | Padding vertical de página (abajo), padding superior del footer |
| × 5 | 70px | Separación entre el contenido y el footer |

Valores fijos que también usa el sitio: 24px 28px (padding de tarjetas de
artículo y avisos), 32px (header de artículo), 42px (separación entre enlaces
de la navbar), 48px / 64px (padding vertical de páginas de listado).

## Contenedor

```css
width: min(1500px, 95%);   /* --container-max */
margin-inline: auto;
```

Todas las secciones (navbar, contenido, footer) usan el mismo contenedor.
Las únicas excepciones de borde a borde son la banda de logo y las tarjetas
promocionales.

## Header

- Alto: 64px (`--header-height`), sticky.
- `scroll-padding-top` igual al alto del header, para que los anclajes no
  queden debajo.

## Breakpoints

Los cortes son los del sitio, mobile first:

| Corte | Qué cambia |
|---|---|
| ≥ 600px | Footer en 2 columnas |
| ≤ 768px | Bento en 1 columna, header de artículo apilado, promos en 1 columna, paddings reducidos |
| ≥ 769px | Línea de tiempo con línea vertical y marcadores |
| ≥ 900px | Cuadrículas de tarjetas a 3 columnas, cifras a 4, footer en marca + 3 columnas, perfil en 2 columnas |
| ≤ 969px / ≥ 970px | Navbar: menú ☰ en móvil, fila completa en escritorio |
| ≤ 1200px | Bento a 6 columnas |

## Cuadrículas

| Cuadrícula | Definición |
|---|---|
| Bento | 12 columnas, filas de 95px, separación 14px (6 columnas en ≤ 1200px, 1 en ≤ 768px) |
| Tarjetas | `repeat(auto-fit, minmax(min(100%, 260px), 1fr))`, 3 columnas fijas desde 900px |
| Cifras | 2 columnas, 4 desde 900px |
| Footer | 1 → 2 → `1.4fr + 3 × 1fr` |
| Promos | 2 columnas con 10px de separación, 1 en ≤ 768px |

## Densidad

- Las páginas de contenido son espaciosas: tarjetas en una columna con 14px
  entre ellas.
- Las secciones de perfil son equilibradas: cuadrículas de 3 columnas.
- El hero Bento es denso: 14px entre tarjetas de distintos tamaños.

# Movimiento

## Una sola curva

```css
--transition-default: .28s cubic-bezier(.2, .8, .2, 1);
```

Todas las transiciones de interfaz (color, borde, sombra, transform,
opacidad) usan esta duración y esta curva: entrada rápida y frenado suave.

## Movimientos del sistema

| Movimiento | Detalle |
|---|---|
| Subrayado de navegación | Barra de 2px que crece de 0 a 100 % del ancho del enlace |
| Elevación de tarjeta de marca | Sube 4px, `contrast(1.4)`; el logo gira de su ángulo a 2° y escala ×1.12 |
| Elevación de tarjeta de proyecto | Sube 2px; la flecha ↗ se mueve 2px arriba y a la derecha |
| Flecha de enlace de tarjeta | Aparece (opacidad 0 → 1) y se desplaza 2px |
| Lupa de búsqueda | Con foco escala ×1.12; con texto y foco "escanea": ciclo de 1.6s con ±3px y ±10° |
| Panel del menú móvil | Fundido + desplazamiento de 8px hacia abajo |
| Resplandor del hero | Flota 6px arriba y abajo en un ciclo de 10s |
| Banda de logo | Las letras suben 4px y escalan ×1.04 |

## Reglas

- Los movimientos son cortos (2–8px) y nunca bloquean la tarea.
- Sin rebotes ni efectos elásticos.
- Con `prefers-reduced-motion: reduce` todas las animaciones y transiciones
  se vuelven instantáneas, sin desplazamientos (incluidas en `base.css` y
  `components.css`).
- Nada parpadea ni destella.

# Accessibility

Accessibility is a product requirement, not a visual variant.

## Minimum requirements

- WCAG 2.2 AA is the target for web products.
- Semantic HTML and meaningful heading order.
- Keyboard access for all interactive controls.
- Visible focus state with sufficient contrast.
- Form controls have labels and understandable errors.
- Images have appropriate alternative text.
- Color is never the only way to communicate meaning.
- Motion-sensitive users can reduce non-essential motion.
- Touch targets should be comfortably usable; aim for at least 44 × 44 CSS px where practical.

## Dark UI considerations

Dark interfaces can cause low-contrast text and controls. Test actual combinations; do not rely on visual intuition.

## Focus

Every interactive element shows a **2px `#B37AC2` outline with a 2px
offset** on `:focus-visible` (global rule in `mxvi/base.css`). Inside clipped
containers (brand tiles) the offset is negative (`-4px`) so the ring stays
visible. Do not remove the focus indicator without replacing it.

## Built into the system

- "Skip to content" link as the first focusable element (`.mx-skip-link`).
- `.mx-visually-hidden` for accessible names and "(external site)" hints.
- Global reduced-motion rule: animations and transitions become instant.
- Contrast of the core palette is verified in [Color](/foundations/colors#contraste).
- Icon buttons are 44 × 44px; decorative icons use `aria-hidden="true"`.

## Validation

Use automated checks (for example axe) and manual keyboard/screen-reader testing. Automated tools do not prove full accessibility.

# Components overview

::: tip Look concreto
Esta página define el **contrato** (propósito, estados y reglas). El aspecto

This section defines the intended contracts for reusable MXVI components. It is a design specification, not yet a published component library.

## Component principles

1. Components consume design tokens.
2. Components expose semantic states.
3. Components support keyboard interaction.
4. Components do not hardcode product-specific brand colors.
5. Variants should solve real use cases, not create arbitrary customization.
6. Composition is preferred over a large number of configuration props.

## State model

Interactive components should consider:

- Default
- Hover
- Focus-visible
- Active / pressed
- Disabled
- Loading
- Error / invalid
- Selected (when applicable)

## Naming

Use clear names such as `Button`, `TextField`, `Card`, `Badge`, `Dialog`, and `Toast`. Keep implementation-specific names out of design documentation unless they are part of the public API.

## Platform adaptation

The contracts on these pages apply to every platform. Sizes, input methods and
OS conventions are adapted in each platform guide:
[Web](/platforms/web/components), [Desktop](/platforms/desktop/components),
[Mobile](/platforms/mobile/components).

## Component maturity

Every component should be marked:
- **Proposed:** documented, not implemented.
- **Experimental:** implemented but API may change.
- **Stable:** reviewed, tested, and safe to reuse.
- **Deprecated:** replacement and removal timeline documented.

# Buttons

::: tip Look concreto
Esta página define el **contrato** (propósito, estados y reglas). El aspecto
exacto, con medidas, colores y código, está en el
[catálogo de componentes](/catalog/atoms/buttons).
:::

## Purpose

Buttons trigger an action. Use links for navigation.

## Variants

| Variant | Catalog class | Purpose |
|---|---|---|
| Accent (primary) | `.mx-button--accent` | Main action in a context |
| Outline (secondary) | `.mx-button` | Supporting action, links with icons |
| Surface | `.mx-button--surface` | Page navigation (next, pagination) |
| Quiet | `.mx-button--quiet` | Low-emphasis action inside cards |
| Small mono | `.mx-button--sm` | Utility actions in bars |
| CTA | `.mx-button--cta`, `--cta-outline` | Promotional sections only |

Destructive actions are not defined yet. **Proposal:** outline button with the
proposed danger color `#F05B72` on border and text, plus an explicit label.

## Rules

- Prefer one primary button per action group.
- Label actions with verbs.
- Use a visible focus state.
- Disabled buttons must remain understandable; explain unavailable actions when necessary.
- Loading state must prevent duplicate submission and communicate progress.
- Destructive actions should use explicit language and confirmation when impact is significant.

## Sizing

Padding defines the size (see the catalog specs); corners are always square. Ensure touch targets reach 44 × 44 px on touch devices.

## Do not

- Use a button only for decoration.
- Use color alone to distinguish destructive actions.
- Place multiple competing primary actions side by side.

# Brand identity

## Esencia

**MXVI** es una identidad para un ecosistema de tecnología, software, ingeniería y contenido educativo.

### Referencia viva

[moisesbaldenegro.com](https://moisesbaldenegro.com) es la expresión de
referencia de MXVI. Si hay dudas sobre cómo debe verse algo, se resuelve
comparándolo con ese sitio y con el [ADN visual](/catalog/visual-dna).

### Propósito

Hacer que los productos y experiencias tecnológicas sean reconocibles, coherentes y claros, sin sacrificar personalidad.

### Personalidad

| Atributo | Significado visual |
|---|---|
| Technical | Precisión, estructura, claridad y detalle |
| Modular | Sistemas, bloques, grids y composición |
| Expressive | Contraste, acentos y personalidad |
| Balanced | Futurismo controlado, no ruido visual |
| Accessible | Jerarquía, legibilidad e interacción clara |

## Principios no negociables

1. La función y legibilidad tienen prioridad sobre la decoración.
2. El color de marca no debe competir con el contenido.
3. Las superficies oscuras crean el lienzo; los acentos crean jerarquía.
4. La composición debe sentirse intencional y modular.
5. Los productos pueden tener personalidad propia sin romper los fundamentos.
6. No utilizar efectos de neón como sustituto de una buena jerarquía visual.
7. Esquinas rectas, líneas finas y un solo acento ciruela: la sobriedad es la firma.

## Tagline

**One identity. Multiple products. A consistent experience.**

## Arquitectura de marca

- **MXVI Web:** sitios, portfolio y landing pages.
- **MXVI Software:** aplicaciones, herramientas y productos SaaS.
- **MXVI Media:** contenido educativo, social y editorial.
- **MXVI Docs:** documentación, conocimiento y recursos técnicos.

Los nombres anteriores son familias de expresión, no necesariamente marcas independientes.

El logotipo se usa siempre con sus colores originales. Las variantes de una
sola tinta quedan para casos donde el color no es posible (impresión, sellos,
fondos que lo exijan).

## Construcción

- Lienzo del logo: `2048 × 716` (proporción ≈ 2.86 : 1).
- Cuatro letras: **M**, **X**, **V** e **I**. La M y la X en morado; la V en
  naranja; la I en naranja con el triángulo morado superior.
- Las piezas se superponen: M en `x = 0`, X en `x = 574`, V en `x = 1025`,
  I en `x = 1858`. No separarlas ni redistribuirlas.

## Reglas

- No estirar, inclinar ni rotar el logotipo.
- No alterar la relación entre letras.
- No añadir sombras o glow permanentes al archivo maestro.
- No colocar sobre fondos que comprometan contraste.
- Mantener una zona libre mínima equivalente a la altura de la letra M.
- No reconstruir el logo con una fuente distinta si existe un SVG oficial.

## Origen

Los SVG de `public/brand/` son los vectores oficiales, tomados del sprite de
moibaldenegro.com (`mxvi-m`, `mxvi-x`, `mxvi-v`, `mxvi-i`) y compuestos con
las posiciones del logotipo maestro. Si el logo cambia, actualizar primero el
sprite del sitio y regenerar estas variantes.

# Visual language

## Dirección

Dark Tech / Modular Bento / Developer Aesthetic.

MXVI debe sentirse como una extensión visual de un entorno de ingeniería moderno: oscuro, preciso, estructurado y expresivo.

## Recursos gráficos

- Esquinas rectas en todo: paneles, botones, tags e imágenes.
- Líneas finas blancas translúcidas (8 % y 15 %) en lugar de cajas pesadas.
- Atmósfera morada: degradado radial `#3C1F44` → `#150A18` → `#05050b` con
  grano de puntos de 1px cada 14px y un resplandor `rgba(108,56,122,.35)`.
- Un solo acento ciruela `#B37AC2` como señal.
- Tipografía Geist Pixel para títulos y etiquetas en mayúsculas.
- Bento de tarjetas de marca con logos gigantes, rotados y recortados.

El detalle completo está en el [ADN visual](/catalog/visual-dna).

## Evitar

- Cyberpunk genérico con exceso de neón.
- Esquinas redondeadas.
- Acentos adicionales (cian, magenta, verde) fuera de sus usos únicos.
- Circuitos aleatorios como decoración universal.
- Rojo/naranja como colores dominantes de marca.
- Glow en todos los elementos.
- Gradientes arcoíris.
- Interfaces que parezcan HUD de videojuego sin necesidad funcional.

## Fotografía

La fotografía debe ser auténtica y conservar su jerarquía. No cubrir rostros, manos relevantes ni elementos esenciales con overlays. Corregir exposición y temperatura antes de aplicar efectos.

# Guidelines overview

Guidelines translate foundations into repeatable decisions.

## Composition checklist

- What is the primary task or message?
- What should be noticed first?
- Which elements are structural and which are decorative?
- Is the content readable at its actual size?
- Does the layout adapt to narrow screens?
- Are brand accents used intentionally?
- Can the composition be recognized as MXVI without relying on the logo?

## Recognition test

A composition is recognizable as MXVI when it has, at least:

- the indigo night background `#070716` with `#101018` surfaces;
- 1px white hairlines (8 % / 15 %) instead of heavy boxes;
- square corners on every element;
- Geist Pixel titles and uppercase labels;
- a single plum accent `#B37AC2` used as a signal;
- the purple atmosphere (gradient, dot grain, glow) on hero blocks.

The full list is the [Visual DNA](/catalog/visual-dna). Build compositions from
[catalog](/catalog/) components before designing new ones.

## Content hierarchy

1. Primary message or task.
2. Supporting explanation.
3. Context and metadata.
4. Decorative elements.

Decoration must never outrank the information it supports.

# Product expression

MXVI supports multiple product types while retaining a shared foundation.

## Shared across all products

- Geist Pixel, Geist Sans and Geist Mono with the documented scale.
- Background `#070716`, surface `#101018`, white hairlines, plum accent `#B37AC2`.
- Square corners and the 14px spacing unit.
- The single transition `.28s cubic-bezier(.2,.8,.2,1)`.
- The catalog components and the official logo.
- Interaction and accessibility principles.

## Allowed to vary

- Information density.
- Product-specific semantic colors.
- Navigation model.
- Data visualization palette extensions.
- Photography and illustration.
- Component composition based on product tasks.

## Product families

| Family | Priority | Expression | Reference |
|---|---|---|---|
| Web | Brand and storytelling | Hero Bento, article feed, promo tiles | moisesbaldenegro.com home |
| Software | Task completion | Navbar, cards, lists, notices; less atmosphere | [Templates](/catalog/templates) |
| Media | Attention and narrative | Brand tiles, promo tiles, full-bleed logo band | [Promo](/catalog/organisms/promo) |
| Docs | Retrieval and comprehension | Prose, code blocks, result rows | This documentation site |

A product may add tokens, but additions must be named, justified, and documented.

## Platforms

Product families describe the purpose of a product; platforms describe where
it runs. Apply the guide for each platform the product ships on:
[Web](/platforms/web/), [Desktop](/platforms/desktop/) and
[Mobile](/platforms/mobile/).

# Bento composition

## Definition

Bento is a modular composition made from rectangular content regions with varied spans. MXVI uses it to express systems, modules, and structured information.

## Rules

- Start with a grid, not arbitrary card placement.
- Establish a clear primary block.
- Use size variation to communicate importance.
- Keep gutters consistent.
- Align edges where possible.
- Maintain a logical reading order in the DOM.
- Reflow modules on smaller screens; do not merely shrink the desktop grid.
- Avoid decorative cards that contain no information or purpose.

## Suggested grid

Desktop: 12 columns with 95px rows and 14px gaps. ≤ 1200px: 6 columns. ≤ 768px: single column. See the [Hero Bento](/catalog/organisms/hero-bento) organism for the reference implementation.

## Common failure modes

- Every card has equal visual weight.
- Too many accent colors compete.
- Content is cropped to fit a shape.
- Reading order differs from visual order.
- Layout depends on fixed pixel dimensions.

# Content and data visualization

## Content

- Lead with the information, not the decoration.
- Use concise headings and descriptive labels.
- Keep long-form content readable.
- Use technical labels for context, not as visual noise.
- Maintain consistent terminology across products.

## Data visualization

**Proposal** (the website has no charts yet). Charts follow the same look:

| Element | Value |
|---|---|
| Plot area | `#101018` with a 1px `rgba(255,255,255,.08)` border, square corners |
| Grid lines | 1px `rgba(255,255,255,.08)`; axis 1px `rgba(255,255,255,.15)` |
| Axis labels and ticks | Geist Mono .75rem `#b8b8c5` |
| Chart title | Geist Pixel, like a section heading |
| Values | Geist Sans 800 for big figures (like [stats](/catalog/molecules/cards#cifra-destacada)) |
| Series 1 → 6 | `#B37AC2`, `#F7941D`, `#5fd6ff`, `#39C98A`, `#F3B64B`, `#F05B72` |
| Bars and areas | square ends, no rounded caps |

Rules:

- Use neutral surfaces and restrained grid lines.
- Reserve accent colors for series or important values.
- Use direct labels when they improve comprehension.
- Do not use 3D effects that distort data.
- Include units, scales, and time ranges.
- Provide a text or tabular alternative when a chart is essential.
- Use color palettes that remain distinguishable for common color-vision deficiencies.

## Semantic colors

Do not use the brand palette as a substitute for a complete categorical data palette. Extend it deliberately and document the mapping.
